# Content Fabric

Фабрика контента: по расписанию генерирует посты через OpenAI (с веб-поиском), подбирает к ним стоковую картинку и публикует в Telegram и Max. Управляется через веб-админку.

## Как это работает

```
Scheduler ──> runs (SQLite) ──> Worker pool (MAX_CONCURRENCY, не более 1 задачи на кампанию)
                                   │
   1. context   системный промпт кампании + общий стайлгайд + последние темы (антиповтор)
   2. generate  OpenAI Responses API: web_search + structured output (JSON по схеме)
   3. validate  длина текста (при необходимости сокращение), проверка URL источников
   4. image     фото из статьи-источника (og:image) или сток Unsplash / Pexels / Pixabay -> sharp -> data/media
   5. render    единый IR -> Telegram HTML / Max HTML / plain, выбор формата TG
   6. review    режим «модерация»: черновик в Telegram админу с кнопками + раздел в админке
   7. publish   Telegram всегда, Max только если задан MAX_BOT_TOKEN
```

- **Telegram**: короткий пост уходит как фото с подписью (≤ 1024 символов), длинный как текст до 4096 символов с картинкой-превью сверху.
- **Max**: текст до 4000 символов в HTML, картинка загружается через `/uploads` и прикрепляется токеном.
- **Идемпотентность**: каждый слот расписания имеет уникальный ключ `кампания|дата|время`, поэтому перезапуск сервиса не создаёт дублей. Слоты, пропущенные дольше `MISFIRE_GRACE_MINUTES`, записываются как «пропущен».
- **Картинки**: два пути. Для конкретных событий модель выбирает `image_strategy = "source"`, и сервис берёт главное фото статьи-источника (`og:image` / `twitter:image`, проверка размера и пропорций, подпись «Фото: сайт» со ссылкой). Для общих тем модель выбирает сток по `image_query`. Сток всегда остаётся запасным вариантом. Режим задаётся в кампании: решает модель / всегда сначала источник / только сток. Интерфейс `ImageProvider` (`server/src/images/provider.ts`) позволяет добавить генерацию картинок как ещё один провайдер, возвращающий кандидата с полем `bytes`.

## Быстрый старт (Docker, VPS)

```bash
cp .env.example .env     # заполните ключи
docker compose up -d --build
# админка: http://<host>:8080  (логин/пароль из ADMIN_USER / ADMIN_PASSWORD)
```

Минимальный `.env`: `ADMIN_PASSWORD`, `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN`. Рекомендуется также `ADMIN_TELEGRAM_CHAT_ID` (для модерации в Telegram) и хотя бы один ключ картинок (`UNSPLASH_ACCESS_KEY` или `PEXELS_API_KEY`).

Данные (SQLite и картинки) лежат в `./data`, он примонтирован в контейнер как `/data`.

### Telegram

1. Создайте бота через @BotFather, положите токен в `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота администратором в каждый канал, куда он будет постить (право «Публикация сообщений»).
3. Напишите боту `/start`: он ответит вашим chat id. Укажите его в `ADMIN_TELEGRAM_CHAT_ID`, чтобы получать черновики с кнопками «Опубликовать / Перегенерировать / Пропустить».
4. В кампании укажите канал как `@username` или числовой id (`-100…`).

### Max

1. Получите токен бота в Max и укажите `MAX_BOT_TOKEN`. Пока токена нет, публикация в Max пропускается, а `maxChatId` в кампаниях сохраняется на будущее.
2. API Max использует сертификат национального УЦ. Положите корневой сертификат (PEM) в `./certs/`, контейнер подхватит его через `NODE_EXTRA_CA_CERTS`. Для локальной отладки есть `MAX_INSECURE_TLS=true`.
3. `chat_id` канала приходит боту в событии `bot_added` после добавления в канал (метод списка чатов в API Max отключён).

### Картинки

- Unsplash: 50 запросов/час на demo-ключе, 5000 после регистрации приложения. Превью в Telegram берутся напрямую с CDN Unsplash, это разрешено их правилами.
- Pexels: 200 запросов/час.
- Pixabay: не разрешает хотлинк, поэтому для длинных постов с превью нужен `PUBLIC_BASE_URL` (картинка отдаётся с `/media/...`).

Если ни один провайдер не настроен, стоковых картинок не будет; фото из источников при этом работают. Если картинку взять неоткуда, пост выходит без неё (или запуск падает с ошибкой, если в кампании включено «картинка обязательна»).

Фото из новостных статей часто защищены лицензией издания или фотоагентства. Сервис всегда добавляет подпись с ссылкой на источник, но ответственность за право перепечатки лежит на владельце канала. Для кампаний, где это критично, выберите режим «Только сток».

### HTTPS и публичный URL

`PUBLIC_BASE_URL` нужен для ссылок на админку в сообщениях модерации и для раздачи собственных картинок (в будущем для сгенерированных). Поставьте перед сервисом Caddy или nginx с TLS, порт приложения 8080.

## Локальная разработка

```bash
npm install
cp .env.example .env            # заполните
npm run dev                      # сервер на :8080 (tsx watch)
npm run dev:admin                # Vite на :5173 с прокси на :8080
```

Сервер ищет `.env` в текущей директории, затем в `server/` и в корне репозитория, поэтому одного файла в корне достаточно. Скрипты `npm run build` / `npm start` собирают и запускают продакшен-версию, админка отдаётся сервером с того же порта.

Изменения схемы БД: правьте `server/src/db/schema.ts` и выполняйте `npm run db:generate`, миграции применяются автоматически при старте.

## Структура

```
server/src
  config.ts            переменные окружения (zod)
  db/                  drizzle-схема, миграции, репозиторий
  scheduler/           тик расписания и очередь воркеров (p-queue)
  pipeline/            конвейер генерации и публикации
  llm/                 OpenAI Responses API, схема черновика
  content/             IR, рендер в Telegram/Max/plain, стайлгайд
  images/              провайдеры картинок (Unsplash, Pexels, Pixabay)
  media/               скачивание, нормализация, хранение
  publishers/          Telegram (grammY) и Max (HTTP) публикаторы
  review/              модерация: Telegram-кнопки и действия
  http/                Fastify: API, basic auth, статика админки и /media
admin/src              React-админка (кампании, модерация, запуски, настройки)
```

## API (basic auth)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET/POST | `/api/campaigns` | список / создание |
| GET/PUT/DELETE | `/api/campaigns/:id` | чтение / изменение / удаление |
| PATCH | `/api/campaigns/:id/enabled` | включить/выключить |
| POST | `/api/campaigns/:id/run` | запустить сейчас, `{ "forceReview": true }` для черновика |
| GET | `/api/runs`, `/api/runs/:id` | запуски и журнал |
| GET | `/api/posts?status=awaiting_review` | посты на модерации |
| POST | `/api/posts/:id/approve\|regenerate\|skip` | решения по черновику |
| GET/PUT | `/api/settings/style-guide` | общий стайлгайд |
| GET | `/api/status`, `/api/models` | состояние сервиса, список моделей |
